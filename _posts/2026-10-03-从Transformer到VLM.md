# 引言

前面已经单独写过 [Transformer 与 ViT](/Transformer/)、[CLIP](/CLIP/)，也写过 [参数量和显存](/大模型参数量与显存估算/)。几篇放在一起读，容易觉得名词都见过，接不上：ViT 的 patch、LLM 的 token、VLM 里的「视觉词」，到底是不是同一种东西。

# 先对一下四个词

| | 序列里的一项是什么 | Attention 能看到谁 | 训练时在逼模型做什么 | 拿出去用的表示 |
| --- | --- | --- | --- | --- |
| Transformer | 任意 token，最初是词 | 由掩码决定 | 翻译、语言模型等任务目标 | 每个位置的向量 |
| ViT | 图像 patch，外加一个 class token | 整张图的全部 patch | 图像分类 | 多半只用 class token |
| LLM | 子词 token | 生成时只看左侧 | 预测下一个 token | 词表上的概率 |
| VLM | 文本 token 和视觉 token 拼在一起 | 问题的 Query 可以打到图像的 Key 上 | 多为「看图之后把回答写出来」 | 仍然常常是文本 |

底层运算可以不变。变的是 token 从哪来、掩码让谁看见谁、损失问的是哪一个位置。


# 一、Attention：当前位置到历史里去取

## 读句子时，权重不会铺均匀

先不看矩阵。读这句话：

> 周三的外场测试改到了周五，因为那天风小。

读到「那天」，要解决的问题很具体：哪一天。目光会回到「周五」。「外场」「测试」「风小」都在前文里，但它们帮不上「是哪一天」这件事，所以不会被平均看一遍。

再往下读到「风小」，问题换了。这时和天气、场地有关的词权重会升上来，「周五」未必还是最亮的那个。权重跟着当前要解决的问题走，这就是 Attention 想模仿的行为。

模型没有目光，它只有向量。每个位置先变成向量，再为这个向量准备三份投影。

## Query、Key、Value

三份投影各干一件事：

* **Query**：当前位置此刻的问题。上面例子里，「那天」发出的问题是「找一个日期」。
* **Key**：每个历史位置交出来的检索线索。用来和 Query 比，判断「你是不是我要找的」。
* **Value**：比对之后真正被搬回来的内容。Key 只负责被匹配，Value 才进入加权和。

可以想成一次检索：Query 是你手上的检索词，Key 是每条记录的索引，Value 是记录正文。索引对上了，正文才按匹配程度混进当前结果。

三份都从同一个向量 $a$ 线性变出来，只是三套权重 $W_Q, W_K, W_V$ 不同：

$$
q = a W_Q, \quad k = a W_K, \quad v = a W_V
$$

$Q, K, V$ 都来自同一条序列时，叫自注意力。后面 VLM 里更常见的做法，也是把图和文拼成一条序列，继续用自注意力，而不是另做一套交叉注意力。交叉注意力是 Query 来自一条序列、Key 和 Value 来自另一条，Flamingo 那类模型用过；LLaVA 之后的主流更喜欢直接拼接。

## 四步算出一个新向量

把一条序列的 $q, k, v$ 按行堆成矩阵 $Q, K, V$，运算是：

$$
\mathrm{Attention}(Q, K, V) = \mathrm{softmax}\left(\frac{QK^{\top}}{\sqrt{d_k}}\right) V
$$

拆开就是四步。

1. **打分**。$S = QK^{\top}$。$S_{ij}$ 是第 $i$ 个 Query 和第 $j$ 个 Key 的点积。点积大，表示两个向量方向接近。方向接近，就被训练成「这个问题和这条线索有关」。
2. **缩放**。每个分数除以 $\sqrt{d_k}$，$d_k$ 是每个头的向量宽度。原因放在下一小节。
3. **归一**。对每一行做 softmax，得到非负、和为 1 的权重。当前位置的输出因此是所有 Value 的加权平均。
4. **取值**。权重矩阵乘 $V$。相关的 Value 占大头，不相关的被压得很小。

softmax 还会把分数差放大。两个分数相差 $\Delta$，权重比大约是 $e^{\Delta}$。差 1，大约 2.7 倍；差再大，大的一项会迅速占满这一行。

拿三个分数 $[2,\ 0,\ -1]$ 做个手算。指数大约是 $[7.39,\ 1,\ 0.37]$，行和约 $8.76$，权重约 $[0.84,\ 0.11,\ 0.05]$。最高分拿走八成多，其余两项还在，并没有只剩一个赢家。

## 为什么要除以 $\sqrt{d_k}$

假设 $q$ 和 $k$ 的每个分量互相独立、均值 0、方差 1。点积是 $d_k$ 个这样的乘积之和，方差就是 $d_k$，标准差是 $\sqrt{d_k}$。宽度从 16 加到 128，典型分数会大一截。

softmax 对尺度很敏感。把上面那组分数看成已经缩放过的结果：若 $d_k = 64$ 却不除以 $\sqrt{64} = 8$，同样的方向会变成 $[16,\ 0,\ -8]$。$e^{16}$ 大约是 $8.9 \times 10^{6}$，第一项的权重会贴到 1，另外两项接近 0。softmax 的梯度里有 $a_i(1-a_i)$ 这种因子，权重一旦贴到 0 或 1，梯度就几乎没了，这一层在训练开头学不动。

除以 $\sqrt{d_k}$ 把初始点积的方差拉回 1 附近。它会改变注意力的结果，是模型定义的一部分。实现里还常在指数之前减去这一行的最大值，那一步只是防止 $e^{z}$ 溢出，不改变 softmax 的值。两件事情经常写在相邻两行代码里，解决的是两件不同的事。

这个方差故事只在随机初始化附近成立。训练一段时间之后，$Q$ 和 $K$ 不再是单位方差的独立分量，分数仍可能慢慢变大。所以根号缩放管的是起步时的尺度。

## 多头：同一句话，同时问几个问题

一个头只能形成一套匹配。读「那天风小」时，日期和天气最好同时被看到。多头就是把宽度拆成几组，每组有自己的 $W_Q, W_K, W_V$，各自做上面的四步，再把结果拼起来，用一个输出矩阵 $W_O$ 混到一起。

头数变多，表达力变强，也直接把缓存撑大：每一头都要为自己的 Key 和 Value 留位置。后面讲 LLM 的显存时会回到这件事。

## 因果掩码：生成的时候不能看右边

上面的权重默认每一行都能看到整条序列。翻译的编码器、ViT、BERT 可以这样，因为输入在计算开始前已经到齐。

生成却不行。模型正在写第 $t$ 个词，第 $t+1$ 个词就是它要预测的东西。训练时如果让它看见右边，损失会变成抄答案。所以在 softmax 之前，把未来位置的分数设成一个很大的负数，权重就会变成 0。这叫因果掩码。

掩码一旦加上，第 $t$ 个位置的输出只依赖 $1 \dots t$。这条约束后来同时决定了两件事：训练时整句可以一次前向算完，推理时旧 token 的 Key、Value 可以缓存下来不再重算。

## 位置：Attention 自己不知道谁在前

把序列里两个 token 对调，如果没有位置信息，它们的 Query、Key、Value 只是跟着内容走，点积并不知道谁原来排在前面。语言里词序会改意思，图像里 patch 的行列也会改意思。

所以要另加位置。原始 Transformer 用一组正弦函数，加到 token 向量上。ViT 用一张可学习的位置表，形状和 token 序列相同，直接相加。现在的大语言模型更常把位置写进 Query 和 Key 的旋转里，也就是 RoPE：旋转角随位置变化，点积对两个位置的相对距离敏感。训练长度以内这很管用；直接拉到远超训练长度的上下文，旋转外推仍会变差，长上下文还得再改注意力本身。那是另一篇的题目，这里先停在「没有位置，Attention 只看见一袋子向量」。

## 一层里面，Attention 旁边还有什么

现代模型把下面几块重复几十次：

* **Attention**：位置之间交换信息。
* **前馈网络**：每个位置自己做一次非线性变换，常见是先升维再降回来。原始 Transformer 大约升到 4 倍；现在很多模型改用带门控的前馈，参数量单独算。它不看别的位置，更像每个 token 私下翻一遍自己的笔记本。
* **残差**：把这一块的输入加回输出。层数一深，网络要学的是「在原来的表示上改一点」，梯度也有一条直路可走。
* **归一化**：把每一层的尺度按住。大模型里常见的是 RMSNorm，放在注意力和前馈之前。

单独看，没有一块像「理解」。能力来自很多层叠在一起之后，再加上一个合适的损失。

## 序列一长，账单长在平方项和缓存上

第 $i$ 个 Query 要和每个历史 Key 做点积。序列长度为 $L$ 时，一张分数矩阵是 $L \times L$，整段序列的注意力计算随 $L^2$ 涨。存储则随 $L$ 线性涨：每个 token、每一层都要留下 Key 和 Value。

用一个 7B 量级、多头注意力不共享的模型估一笔账。隐藏维度 4096、32 层、32 头、每头 128 维、权重按 FP16。每个 token 在一层里要存的 Key 和 Value 是 $2 \times 32 \times 128 = 8192$ 个数，32 层、每数 2 字节，大约 512 KB。上下文开到 8192，光 KV cache 就在 4 GB 上下。同一模型的权重本身，FP16 大约 14 GB。上下文再拉长，缓存会追平甚至超过权重。

分组共享 Key、Value 能把这个数降下来，那是工程上的下一步。显存还要加上激活、框架开销和量化之后的字节数，算法写在 [显存那篇](/大模型参数量与显存估算/) 里。这里只需要一个结论：Attention 让每个位置都能按需回顾历史，回顾的代价就是长度。


# 二、LLM：同一套块，损失换成「下一个词」

## 一句话的概率被拆成一串条件概率

大语言模型几乎都是自回归的。已经有了左边的 token，再预测右边下一个。整句的概率按链式法则拆开：

$$
P(x_1, \ldots, x_T) = \prod_{t=1}^{T} P(x_t \mid x_{<t})
$$

训练时取负对数再对位置平均。概率越接近把正确的下一个词放在高位，这一项越小。随机初始化时，模型对词表里每个词差不多一视同仁，损失会落在 $\ln(\text{词表大小})$ 附近。词表大约五万时，这个锚点在 11 左右。训练脚本第一步如果离它很远，多半是标签错位或者词表没对上，不必先怀疑优化器。

模型看到的不是汉字或英文单词，而是分词器切出来的子词。后面说的序列长度，数的都是这种 token。图像进 VLM 之后，一个 patch 也会占掉同一个长度预算里的一格。

## 训练可以整句并行，生成必须一个一个来

因果掩码让第 $t$ 位只看左边，所以训练时可以把整句一次送进去：每个位置的标签就是它右边那个真实 token。语料里的前缀是现成的，不用等模型自己写。这种用真实前缀当条件的做法，就是之前笔记里的 [Teacher Forcing](/teacher-and-student-forcing/)。

生成时真实的下一个词还不存在。模型先从最后一位的分布里取出一个 token，把它接到末尾，再算一步。条件的形式没变，条件的来源变了：训练看的是人写的上文，推理看的是模型自己刚写的上文。自己写歪一个词，后面就站在一条训练时少见的前缀上，误差会往后叠。

## 猜下一个词，为什么会带出知识

这个损失表面上看只是在拟合「什么词经常跟着什么词」。要把它做低，模型得把语料里的规律压进权重：词法、搭配、事实、一段代码里变量从哪来。补全「法国的首都是」，靠的是语料里反复出现的对应；补全一段缺少的控制流，靠的是代码里的规律。这些都是压缩这份数据时的副产品。

压缩的是哪批文本，学到的就是哪批文本里能被预测的东西。语料里没有的关系，这个目标不会凭空变出来。即便句子「A 是 B」出现了很多次，反过来问「B 是 A」也不保证同样好答，因为训练只练习过从左往右。损失下降说明模型更会预测这份数据，不能直接当成事实核查通过。

## 为什么主流几乎都是只有解码器

BERT 那条路把一些 token 遮住，让每个位置看到左右两侧再把被遮住的词还原，适合理解，不适合自由地往下写。ViT 也是编码器：分类时整张图已经在手里，不需要因果掩码。

只有解码器的模型成为大语言模型的默认形状，主要是三笔账：

* 同样一次前向，自回归几乎每个位置都有监督；遮挡模型一次只用一小部分位置做标签。
* 因果掩码和推理时的 KV cache 是同一条约束，训练完就能逐 token 生成。
* 很多任务都能写成「给一段前缀，把后面续上」，不必为每个任务另接一个分类头。

单向性的代价还在。判断一句话的转折，往往要看到后半句。模型变大之后，可以用更长的上文和更强的表示补上一部分，单向性本身没有消失。

## 预训练之后，还有两步才像在对话

只做下一个词，模型会续写网页，不会稳稳地回答问题。后面通常还有两步，损失的位置不一样。

**指令微调**仍是下一个词，但数据换成「问题，回答」。问题那一段的标签丢掉，只让回答部分产生损失。模型于是学会在这种版式下把回答写出来。

**偏好对齐**比较两条回答。人或者另一个模型认为其中一条更好。RLHF 用奖励模型和强化学习去推高较好的那条；DPO 把同一件事收成一个直接的分类式损失，不再单开一条强化学习循环。两种做法都是在改「同样的问题下，哪一种续写更常出现」，不是在 Attention 里加新的算子。

## 推理时，贵的常常是缓存

提示词阶段可以把整段 prompt 并行算完，把每一层的 Key、Value 留下，这一段叫 prefill。之后每生成一个 token，只算新 token 的 Query，并和缓存里的 Key 做匹配，这一段叫 decode。Decode 的算术强度往往不高，时间更多花在把缓存从显存里读出来。

所以「参数量」和「这次能不能跑」是两本账。权重决定模型文件有多大；上下文长度、层数、KV 头数和精度决定缓存有多大。7B、70B 这些名字只回答第一本账。


# 三、ViT：把一张图切成可以做 Attention 的词

## 图像原来不是序列

Attention 要的输入是 `[个数, 维度]`。一张图是 `[高, 宽, 通道]`。2020 年的 ViT 做了一件很硬的事：把图切成固定大小的小块，每块展平，过一个线性层，变成一个 token。论文标题里的 “16×16 words”，说的就是这件事。

在这之前，视觉榜单主要是卷积神经网络。ViT 说明：切块之后，视觉可以用和语言同一个编码器。这一步还没有语言。它只是把图变成了序列。

## 用 ViT-B/16 把形状走一遍

输入 $224 \times 224 \times 3$，patch 边长 16。一边可以切 $224 / 16 = 14$ 块，一共 $14 \times 14 = 196$ 个 patch。每个 patch 有 $16 \times 16 \times 3 = 768$ 个数，所以每个 token 的长度是 768。

线性嵌入在代码里经常写成卷积：核大小 16、步长 16、768 个输出通道。卷积一次做完「切块 + 线性变换」，得到 `[14, 14, 768]`，再把高和宽摊平，就是 `[196, 768]`。

<div align="center">

</div>

<p align="center"><em>图 6：三维的图被收成 Transformer 要的二维矩阵。每个小块是一个 token</em></p>

分类还需要一个汇总向量。ViT 在 196 个 patch 前面拼一个可学习的 class token，长度同样是 768，序列变成 197。位置表是另一组可学习参数，形状 `[197, 768]`，和 token 相加。Attention 不管顺序，这张表负责记住每个 patch 来自原图的哪一行、哪一列。

<div align="center">
  <img src="https://kwanwaipang.github.io/ubuntu_md_blog/images/微信截图_20250312141011.png" width="92%" />
</div>

<p align="center"><em>图 7：每个位置学到的编码，和其余位置做余弦相似度。最亮的是自己；同一行、同一列也偏亮。二维网格被写进了这张表</em></p>

编码器就是标准的块重复堆叠。每一块里，先对每个 token 做 LayerNorm，再多头注意力，然后是两层全连接：768 升到 3072，再回到 768，中间用 GELU。残差把输入加回来。输出形状仍是 `[197, 768]`。

</div>

<p align="center"><em>图 8：ViT 的一层。和语言模型的一层是同一类零件，只是没有因果掩码</em></p>

分类只需要那个 class token 对应的 768 维向量，再过一个线性层得到类别。在大数据集上预训练时，这个头可以是两层；迁到小数据集上，常常一层就够。

## 这套形状后来被 VLM 改了哪里

ViT 为分类准备了一个汇总口。VLM 如果只把这一个向量交给语言模型，空间就没了：模型知道「图里大概有猫」，不知道猫在左上还是右下。所以后面的多模态模型通常留下整张 patch 网格，有时再把相邻 patch 合并，用来少占序列长度。

另外两件 ViT 自己没做的事，会变成 VLM 的短板：

* 对比学习或分类损失鼓励的是高层语义。像素级的笔画、小字、精细位置，在这个目标里可有可无。
* 早期 ViT 把图缩到固定边长。单据、长图、极端宽高比会被挤变形。后来的视觉语言模型才把「原生长宽比、可变分辨率」补回来。

patch 的大小也在变。16 是 ViT 论文里的代表数字，后来也有 14。patch 越小，token 越多，细节越多，Attention 的平方项也越重。


# 四、VLM：让提问的 Query 打到图像的 Key 上

## CLIP：先把图和句子放进同一个坐标系

ViT 能看图，语言模型能读写。两边的向量空间各训各的，点积没有意义。2021 年的 CLIP 用对比学习把它们拉到一处。

一个 batch 里有 $N$ 对图文。图像走视觉编码器，可以是 ResNet，也可以是 ViT；文本走一个 Transformer 编码器。两条塔各自再投影到同一维度。$N$ 个图像向量和 $N$ 个文本向量两两做相似度，得到一个 $N \times N$ 的矩阵。

对角线是真正配过对的图和句子，相似度要被拉高。其余格子来自别的样本，相似度要被压低。模型不用预测整句原文，只需要在这个矩阵里把正确的一对认出来。OpenAI 用了大约四亿对图文来做这件事。

CLIP 擅长检索和粗分类。它给出的是一个图像向量和一个文本向量是否接近，不会把答案写成一段话，也数不清图里有几个人。后来很多模型把 CLIP 的损失换成 SigLIP 那种逐对的 sigmoid 形式，训练更稳，角色没变：仍然是一双用语言监督出来的眼睛。

## 给语言模型接上这双眼睛

2023 年前后，一个很省的接法被做成了可以复现的配方，LLaVA 是其中最常被引用的一个：

1. 用已经训好的 CLIP ViT 读图，取出 patch 网格上的向量，而不是只留 class token。
2. 用一个线性层，或者后来更常见的两层 MLP，把这些向量的维度对上语言模型的词向量。
3. 把它们当作一段「视觉词」，插进文本 token 中间，交给一个已经会对话的 LLM。
4. 损失仍然是下一个词，而且通常只落在回答上。

投影层做的是坐标系对齐。视觉向量和词向量维度、数值尺度都不一样，不投影的话，后面的 $QK^{\top}$ 没有可学习的共同地面。投影本身很浅，几何和语义的重活分别留在 ViT 和 LLM 里。

拼进同一条序列之后，第一节的机制就直接生效。用户问题里每个字的 Query，可以去和图像 patch 的 Key 比；相关的图像 Value 被加进这些字的表示。模型「看见图」并没有新的注意力公式，只是历史里多了一种 token。

这也解释了它为什么能接在已经训好的 LLM 上。对话、指令格式、世界知识都在语言模型的权重里。视觉侧如果从零和语言模型一起训，数据和步数都要重来一遍。冻结或轻调视觉编码器、只重点训练投影和语言模型的一部分，是这条路线能铺开的原因。

Qwen-VL、InternVL 以及后来的 Qwen2.5-VL，骨架仍是「视觉编码器 + 连接层 + 语言模型」。往上加的是使用时才会碰到的问题：可变分辨率、原生长宽比、把视觉 token 合并以缩短序列、让位置编码在大图上仍然有效。OCR 和小目标定位变好，往往是因为 token 更密、训练数据里有了文字和框，而不是 Attention 被换成了别的算子。

## 理解做强了，生成还是另一件事

上面这条链路的图像只作为输入。模型写出文字，画不出一张新图，也改不了图里的一个物体。要把生成接进来，先得看两种视觉 token 要的东西有多不一样。

| | 拿来理解 | 拿来生成 |
| --- | --- | --- |
| 常见前端 | CLIP / SigLIP 这类 ViT | VQ-VAE，或连续的 VAE |
| 训练信号 | 图文是否配对 | 能不能把像素或潜变量重构回来 |
| 表示 | 连续向量，偏语义 | 离散码，或低层潜变量，偏像素 |
| 结构 | 只要编码器 | 编码器之外还要一条解码回图像的路 |

理解要回答「这是不是一只猫」。生成要回答「这只猫的毛边、光和背景像素长什么样」。一个目标把细节扔掉才好泛化，另一个目标把细节留住才能画回来。码的形式也不一样：一边是连续向量，一边常常是码本里的整数。

## 三种处理冲突的办法

**一套码走到底。** Meta 的 Chameleon 用同一个 VQ 前端把图像变成离散 token，和文字 token 排进同一条自回归序列。生成能做，因为重构码本本来就是为了把图编出来。理解会弱，因为这个码本没有为「和图注对齐」优化过。后来也有工作试图在同一个分词器里同时加重构损失和对比损失，两套目标仍会抢同一组表示。

**两套编码器，一个语言模型。** DeepSeek 的 Janus / Janus-Pro 把编码拆开。理解走 SigLIP，得到语义向量，用一个两层 MLP 对齐到语言模型；生成走 VQ 码本，再用另一个适配层对齐。两边拼成一条序列，交给同一个自回归 Transformer。文本用语言模型原来的预测头，图像用另一个预测头。这样选择权回到了任务：语义和像素各用自己擅长的前端。代价也明确，两套表示在进语言模型之前仍然分开，模型结构是接出来的。

**注意力共享，其余参数按任务分开。** 字节的 BAGEL 常被放在这条讨论里，但论文并没有拿掉视觉前端。理解侧仍是 SigLIP2 的 ViT，经两层 MLP 进入语言模型；生成侧用 FLUX 的 VAE 把图像压到潜空间，再切成 token。真正改的是 Transformer 内部：理解专家处理文本和 ViT token，生成专家处理 VAE token，自注意力是共享的。所有 token 能在注意力里互相看见，前馈和一部分投影则各走各的参数。公开权重是大约 14B 总参数、7B 激活，语言模型底座来自 Qwen2.5。它说明「统一」可以发生在注意力这次混合上，同时仍然保留两种视觉 token。

有的介绍会把第三条写成「不要 ViT、不要扩散，图像 patch 直接进出一个解码器」。那是更激进的一种设计，和 BAGEL 的实际结构不是同一件事。读模型卡时值得分开看：前端有几套，注意力共不共享，生成时预测的是离散码还是连续潜变量。

## 声音和视频，仍然是序列问题

图文之外再加音频、视频，产品上会叫全模态。GPT-4o 把文本、图像、音频放进同一次交互里，让这个词被记住。Qwen-Omni 则把「想」和「说」拆成并行的两段：一段读入各种模态并写出文本，另一段把文本转成语音流，前一段还没写完，后一段就可以开始出声。

从这篇笔记的尺度看，新增模态没有更换 Attention。音频帧、视频帧都要先变成 token，再来抢同一条序列的长度。帧率、分辨率和采样率不同，token 的密度差很多，训练时谁占多少比例，会直接决定某一路会不会被另外一路盖住。序列变长之后，第一节那笔 $L^2$ 和 KV cache 的账会重新变成主账单。

图像生成也未必放进同一个权重。有的系列把画图留在单独的模型里，全模态模型负责听、看、说。这是系统划分，不是 Attention 做不到，而是数据、损失和延迟要分开算。


# 和机器人这边的笔记怎么接

视觉语言模型把语义接进了序列，空间尺度并没有自动出现。只在图文上对齐过的模型，对距离、遮挡和可通行区域仍然可能没有度量。之前写 [空间基础模型](/Spatial-Foundation-Model/) 时关心的就是这件事：语言 token 是一维的，机器人要的几何是三维的。

导航和操作则是在 VLM 外面或里面再接动作。[具身智能导航](/具身智能导航/) 和 [VLA 综述笔记](/VLA-survey-2025/) 里，视觉编码器经常仍是 ViT，语言模型仍是上一节的解码器，动作要么是额外的 token，要么交给一个更小的控制模块。骨架没有换，损失从「下一个词」变成了「下一个词，或者下一段轨迹」。

所以这条线到 VLM 并没有结束。它只是说明：等图像、语言和动作都能变成同一种序列，剩下的问题会回到 Attention 已经暴露过的那些地方，也就是长度、缓存、以及每种 token 到底保留了哪一层信息。
