# 先对一下四个词

| | 序列里的一项是什么 | Attention 能看到谁 | 训练时在逼模型做什么 | 拿出去用的表示 |
| --- | --- | --- | --- | --- |
| Transformer | 任意 token，最初是词 | 由掩码决定 | 翻译、语言模型等任务目标 | 每个位置的向量 |
| ViT | 图像 patch，外加一个 class token | 整张图的全部 patch | 图像分类 | 多半只用 class token |
| LLM | 子词 token | 生成时只看左侧 | 预测下一个 token | 词表上的概率 |
| VLM | 文本 token 和视觉 token 拼在一起 | 问题可以打到图像那几格上 | 多为看图之后把回答写出来 | 仍然常常是文本 |

底层运算可以不变。变的是 token 从哪来、掩码让谁看见谁、损失问的是哪一个位置。


# 一、Transformer：Attention 在做什么

循环网络要等上一时刻算完，才能算下一时刻，能记住的距离也很有限。Transformer 把这件事换成：每个位置直接去看整段历史，谁相关谁的权重大。能并行，是因为这些比较可以写成矩阵乘法。记忆能拉多长，则取决于愿意为这段历史付多少计算和缓存。下面先把「相关」说成人在读句子，再落到公式。

## 读到一个字，眼睛不会在每个字上停一样久

先不看矩阵。读这句话：

> 周三的外场测试改到了周五，因为那天风小。

读到「那天」，脑子里要解决的只有一件事：哪一天。视线会落回「周五」。「外场」「测试」「风小」都在前面，对「是哪一天」帮不上忙，停留就短。

句子再往下，读到「风小」，问题换了。这时和场地、天气有关的词会重新变亮，「周五」未必还是最亮的那个。权重跟着当前要解决的问题走，不会把前文均匀扫一遍。

模型没有视线，只有向量。每个已经读过的位置都先变成一个向量，再从这个向量里拆出三份东西，专门配合上面这种「先提问、再核对、最后把内容拿回来」。

## 三份东西：要问的、用来对的、真正取回的

还是「那天」这个位置。

* **Query，要问的问题。** 「那天」发出的问题是：找一个日期。
* **Key，每个旧位置交出来的对得上与否。** 「周五」的线索像一个日期，「风小」的线索像一种天气。和「找日期」这个比，前者分高，后者分低。
* **Value，对上之后真正混进结果的内容。** Key 只负责被比较。分高的位置，把它的 Value 多拿一些过来；分低的位置少拿。于是「那天」这个位置新得到的向量里，日期信息占了大头。

换到「风小」，Query 变成「和风有关的场景是什么」。同一批 Key 会给出另一组分数，「外场」这一类位置的 Value 就被多取一些。历史没变，取回来的混合物变了。

三份都是从同一个向量 $a$ 用不同的线性变换得到的：

$$
q = a W_Q, \quad k = a W_K, \quad v = a W_V
$$

$Q, K, V$ 都来自同一条序列，叫自注意力。如果 Query 来自一条序列，Key 和 Value 来自另一条，叫交叉注意力。后面的视觉语言模型两种都出现过，到第四节再分开说。

## 四步变成一个新向量

把一条序列的 $q, k, v$ 按行堆成矩阵，就是教科书上的式子：

$$
\mathrm{Attention}(Q, K, V) = \mathrm{softmax}\left(\frac{QK^{\top}}{\sqrt{d_k}}\right) V
$$

对应刚才的阅读过程：

1. **打分。** $S = QK^{\top}$。$S_{ij}$ 是第 $i$ 个问题和第 $j$ 条线索的点积。方向越接近，分越高，也就是「这个问题和这条线索更配」。
2. **把分数的尺度按住。** 除以 $\sqrt{d_k}$。$d_k$ 是每头向量的宽度。下一小节说为什么要除。
3. **变成权重。** 每一行做 softmax，得到非负、加起来等于 1 的数。当前位置的输出就是所有 Value 的加权平均。
4. **把内容拿回来。** 权重矩阵乘 $V$。配得上的 Value 占大头。

softmax 还会把差距拉开。两个分数差 $\Delta$，权重比大约是 $e^{\Delta}$。差 1，大约 2.7 倍。

拿三个分数 $[2,\ 0,\ -1]$ 算一下。指数大约是 $[7.39,\ 1,\ 0.37]$，行和约 $8.76$，权重约 $[0.84,\ 0.11,\ 0.05]$。最高的那项拿走八成多，另外两项还在。读「那天」的时候，「周五」很亮，「外场」仍留着一点，就是这种分布，不是只剩一个赢家。

## 为什么要除以 $\sqrt{d_k}$

假设 $q$ 和 $k$ 的每个分量互相独立、均值是 0、方差是 1。点积是 $d_k$ 项这样的乘积加在一起，方差就是 $d_k$，标准差是 $\sqrt{d_k}$。向量越宽，原始分数越容易偏大。

softmax 吃不消太大的分数。上面那组 $[2,\ 0,\ -1]$ 如果只是缩放过的结果，而 $d_k = 64$ 时忘了除以 8，同样的方向会变成 $[16,\ 0,\ -8]$。$e^{16}$ 大约是 $8.9 \times 10^{6}$，第一项的权重会贴到 1，另外两项接近 0。梯度里有 $a_i(1-a_i)$ 这样的因子，权重贴到 0 或 1 时，这一层在训练开头几乎收不到更新。

除以 $\sqrt{d_k}$，是为了让初始点积的方差回到 1 附近。它会改变注意力结果，属于模型定义。代码里指数之前再减去这一行的最大值，只是避免 $e^{z}$ 溢出，不改变 softmax 的值。两行常常挨在一起，管的是两件事。

这套方差假设只在随机初始化附近成立。训练一段时间后，分数仍可能慢慢变大，根号缩放管的是起步时的尺度。

## 多头：同一句话同时问几件事

一个头只能形成一套匹配。「那天风小」里，日期和天气最好一起被看到。多头把宽度拆成几组，每组有自己的 $W_Q, W_K, W_V$，各自做上面的四步，再拼起来，用一个 $W_O$ 混到一起。

头一多，每一头都要留自己的 Key 和 Value。后面算语言模型的缓存时，这笔账会直接出现。

## 生成时不能看右边

上面的权重默认每一行能看到整段输入。翻译的编码器可以这样，因为左右两边的句子都已经在手里。ViT 和 BERT 也可以，输入在计算前就到齐了。

往下写字不行。模型正在写第 $t$ 个词，第 $t+1$ 个词正是它要猜的。训练时如果让它看见右边，损失就变成抄答案。softmax 之前把未来位置的分数设成一个很大的负数，那些权重就变成 0。这是因果掩码。

加上掩码之后，第 $t$ 个位置只依赖 $1 \dots t$。训练时整句仍可以一次送进去，因为右边的正确答案已经写在语料里，只是不让当前位看见。推理时，旧位置的 Key、Value 也可以先存下来，不必每生成一个词都重算整段。

## 不另加位置的话，顺序是丢的

两个 token 对调之后，如果没有位置信息，Query、Key、Value 只跟着内容走，点积不知道谁原来排在前面。「测试改到周五」和「周五改到测试」会混在一起。图像里，patch 的行列同样会改意思。

所以要另加位置。最初的 Transformer 用一组正弦函数，加到 token 向量上。ViT 用一张可学习的表，形状和 token 序列相同，直接相加。现在的语言模型更常把位置写进 Query 和 Key 的旋转里，也就是 RoPE：旋转角随位置变化，点积对两个位置相差多远敏感。训练长度以内这很好用。直接拉到远超训练长度的上下文，外推仍会变差。长上下文要改的是记忆怎么存，那是后面语言模型的工程问题。这里先记住：没有位置，Attention 看见的只是一袋子向量。

## 一层里不只有 Attention

把下面几块重复几十次，就是一个 Transformer 层：

* **Attention**：位置之间交换信息，也就是上面的取内容。
* **前馈网络**：每个位置自己做一次非线性变换，常见是先升维再降回来。最初大约升到 4 倍宽。它不看别的位置，像每个 token 私下整理刚刚取回来的东西。
* **残差**：把这一块的输入加回输出。层数一深，要学的是「在原来的表示上改一点」，梯度也有一条直路。
* **归一化**：把每一层的尺度按住。大模型里常见 RMSNorm，放在注意力和前馈之前。

# 二、ViT：同一套 Attention，输入换成图像小块

## 图不是序列，先切成序列

Attention 要的输入是 `[个数, 维度]`。一张图是 `[高, 宽, 通道]`。2020 年的 ViT 把图切成固定大小的小块，每块展平，过一个线性层，变成一个 token。论文标题里的 “16×16 words”，说的就是这一个动作。

在这之前，视觉榜单上主要是卷积网络。ViT 说明切块之后，看图可以用和读句子同一个编码器。这一步还没有语言。它只是让图像进得了上一节的运算。

## 用 ViT-B/16 把形状走一遍

输入 $224 \times 224 \times 3$，patch 边长 16。一边切 $224 / 16 = 14$ 块，一共 $14 \times 14 = 196$ 个 patch。每个 patch 有 $16 \times 16 \times 3 = 768$ 个数，所以每个 token 长 768。

线性嵌入在代码里经常写成卷积：核 16、步长 16、768 个输出通道。一次卷积做完切块和线性变换，得到 `[14, 14, 768]`，再把高和宽摊平，就是 `[196, 768]`。

## 这套形状留给后面的接口

ViT 为分类准备了一个汇总口。如果后面只把这一个向量交给语言模型，空间就没了：模型知道图里大概有猫，不知道猫在左上还是右下。视觉语言模型通常留下整张 patch 网格，有时再把相邻小块合并，少占序列长度。

另外两件 ViT 自己没做的事，会变成多模态里的短板。分类损失鼓励的是「这张图属于哪一类」，笔画、小字、精细位置在这个目标里可有可无。早期实现还把图缩到固定边长，单据和长图会被挤变形。patch 用 16 是论文里的代表数字，后来也有 14。小块越小，token 越多，细节越多，上一节那个 $L^2$ 也越重。


# 三、LLM：损失换成下一个词

第二节的编码器和这一节的语言模型，中间隔着的是训练目标，不只是层数。大语言模型几乎都只保留带因果掩码的解码器：词表里取出一个 token，加上位置，堆很多层，最后用一个线性层投回词表，得到下一个 token 的概率。

## 一句话被拆成一串条件概率

已经有了左边，再预测右边下一个。整句概率按链式法则拆开：

$$
P(x_1, \ldots, x_T) = \prod_{t=1}^{T} P(x_t \mid x_{<t})
$$

训练时取负对数，再对有效位置平均。正确的下一个词概率越接近 1，这一项越小。实现上把标签相对输入错开一位：位置 $t$ 的监督是第 $t+1$ 个 token。长度为 $T$ 的一段文本，一次前向大约给出 $T-1$ 个监督。遮挡模型一次通常只在大约一成多的位置上出题，同样的算力，自回归拿到的监督更密。

随机初始化时，模型对词表里每个词差不多一视同仁，损失会落在 $\ln(\text{词表大小})$ 附近。词表大约五万，这个锚点在 11 左右。训练第一步如果离它很远，先查标签有没有对齐、词表有没有配错。

模型看到的不是汉字或英文单词，而是分词器切出来的子词。后面说的长度，数的都是这种 token。等图像再进来，一个 patch 也会占掉同一个预算里的一格。

## 训练可以整句并行，生成必须一个一个来

因果掩码让第 $t$ 位只看左边，所以训练可以把整句一次送进去。语料里的前缀是现成的，不用等模型自己写。这种用真实前缀当条件的做法，就是之前笔记里的 [Teacher Forcing](/teacher-and-student-forcing/)。

生成时下一个词还不存在。模型从最后一位的分布里取出一个 token，接到末尾，再算一步。条件分布的形式没变，条件从哪来变了：训练看的是人写的上文，推理看的是模型自己刚写的上文。自己写歪一个词，后面就站在一条训练时少见的前缀上，误差会往后叠。

## 把下一个词预测准，就会把规律压进权重

这个损失表面上看是在拟合「什么词经常跟着什么词」。要把它做低，模型得把语料里能帮助预测的规律放进权重：词法、搭配、事实、一段代码里变量从哪来。补全「法国的首都是」，靠的是语料里反复出现的对应；补全缺少的控制流，靠的是代码里的规律。这些是压缩这份数据时带出来的，不是单独开了一门知识课。

压缩的是哪批文本，能预测的就是哪批文本里的规律。语料里没有的关系，这个目标变不出来。即便「A 是 B」出现了很多次，反过来问「B 是 A」也不保证同样好答，因为训练只练习过从左往右。损失下降说明模型更会预测这份数据，不能直接当成事实已经核对过。

## 为什么主流几乎只留解码器

BERT 把一些 token 遮住，让每个位置看到左右两侧，再把被遮住的词还原。这适合理解一段已经写完的文本，不适合自由地往下写。ViT 也是编码器：分类时整张图已经在手里。

只有解码器的模型成为默认形状，主要是三笔账。

* 一次前向里，几乎每个位置都有下一个词可以学。
* 因果掩码和推理时的缓存是同一条约束，训练完就能逐 token 往下写。
* 很多任务都能写成「给一段前缀，把后面续上」，不必为每个任务另接一个分类头。

单向性的代价还在。判断一句话的转折，常常要看到后半句。模型变大之后，可以用更长的上文补上一部分，从左到右这个限制还在。

## 预训练之后，还有两步才像在对话

只做下一个词，模型会续写网页。要它按问题作答，通常还有两步，改的是数据，不是 Attention 的公式。

**指令微调**仍是下一个词，数据换成「问题，回答」。问题那一段不产生损失，只让回答部分产生损失。实现里常把不算损失的位置标成一个忽略值，交叉熵直接跳过。模型于是学会在这种版式下把回答写出来。

**偏好对齐**比较两条回答，其中一条被认为更好。RLHF 用奖励模型和强化学习去抬高较好的那条。DPO 把同一件事收成直接的分类式损失，不再单开一条强化学习循环。两种做法都是在改「同样的问题下，哪一种续写更常出现」。

## 推理时，长度的账单在缓存上

提示词阶段可以把整段 prompt 并行算完，把每一层的 Key、Value 留下，这一段叫 prefill。之后每生成一个 token，只算新 token 的 Query，并和缓存里的 Key 做匹配，这一段叫 decode。Decode 的算术强度往往不高，时间更多花在把缓存从显存里读出来。

用一个 7B 量级、多头不共享 Key/Value 的模型估一笔。隐藏维度 4096、32 层、32 头、每头 128 维、按 FP16。每个 token 在一层里要存的 Key 和 Value 是 $2 \times 32 \times 128 = 8192$ 个数，32 层、每数 2 字节，大约 512 KB。上下文开到 8192，光这份缓存就在 4 GB 上下。同一模型的权重，FP16 大约 14 GB。上下文再拉长，缓存会追平甚至超过权重。

分组让若干头共用同一套 Key、Value，能把这个数降下来。显存还要加上激活、框架开销和量化之后的字节数，算法写在 [显存那篇](/大模型参数量与显存估算/)。这里的结论只服务后面的多模态：每多一种模态，都是在往这条序列里加 token，长度的账单会一起涨。


# 四、VLM：图和文进同一次 Attention

ViT 能看图，语言模型能把字写下去。两边的向量如果各训各的，点积没有意义。2021 年之后的多模态模型，就是在补这一段。可以分成几步看，每一步改的东西不一样。

| 台阶 | 大约何时 | 新接上的能力 | 代表 |
| --- | --- | --- | --- |
| 图像变成 token | 2020 | 分类 | ViT |
| 图和文落在可比较的空间 | 2021 | 检索、零样本分类 | CLIP，后来的 SigLIP |
| 语言模型读这些视觉 token 并写回答 | 2023 起 | 看图问答 | LLaVA、Qwen-VL、InternVL |
| 理解和生成抢同一套视觉表示 | 2024 起 | 既看懂，也画出或改图 | Chameleon、Janus-Pro、BAGEL |
| 声音、视频也变成 token | 再往后 | 听、看、说放进同一次交互 | GPT-4o、Qwen-Omni 这一类 |

## CLIP：先让图和句子能够比较

一个 batch 里有 $N$ 对图文。图像走视觉编码器，可以是卷积网络，也可以是 ViT。文本走一个 Transformer 编码器。两条塔再投影到同一维度。$N$ 个图像向量和 $N$ 个文本向量两两做相似度，得到 $N \times N$ 的矩阵。

对角线是原来配过对的图和句子，相似度要被拉高。其余格子来自别的样本，相似度要被压低。模型不用把整句原文写出来，只要在这个矩阵里把正确的一对认出来。OpenAI 用了大约四亿对图文做这件事。

## 把视觉 token 插进已经会写字的模型

2023 年前后，一个很省的接法被做成了可以复现的配方。LLaVA 是其中最常被引用的一个。

1. 用已经训好的 CLIP ViT 读图，取出 patch 网格上的向量，留下空间，而不是只留 class token。
2. 用一个线性层，或者后来更常见的两层 MLP，把这些向量的维度对上语言模型的词向量。
3. 把它们当作一段视觉 token，插进文本 token 中间，交给一个已经会按指令续写的语言模型。
4. 损失仍然是下一个词，而且通常只落在回答上。

投影层做的是坐标系对齐。视觉向量和词向量的维度、数值尺度都不一样。不投影的话，后面的 $QK^{\top}$ 没有可学习的共同地面。投影本身很浅，看图的几何留在 ViT 里，把字写顺留在语言模型里。

拼进同一条序列之后，第一节的机制直接生效。问题里每个字的 Query，可以去和图像 patch 的 Key 比；配得上的图像 Value 被加进这些字的表示。模型读到图，靠的是历史里多了一种 token，不是又发明了一种注意力。

这也解释了它为什么能接在已经训好的语言模型上。对话格式和从文本里压出来的规律都在那些权重里。视觉侧如果从零和语言模型一起训，数据和步数都要重来一遍。冻结或轻调视觉编码器、重点训练投影和语言模型的一部分，是这条路线能铺开的原因。

这里用的是自注意力：图和文先拼成一条，再互相看。Flamingo 那一类则是交叉注意力，Query 来自文本，Key 和 Value 来自图像特征。两条路都能让文字读到图。2023 年之后开源模型更常选择拼接，因为实现上就是在语言模型的输入序列里插入一段向量。

Qwen-VL、InternVL，以及后来的 Qwen2.5-VL，骨架仍是视觉编码器、连接层、语言模型。往上加的是用的时候才会碰到的问题：可变分辨率、原生长宽比、把相邻视觉 token 合并以缩短序列、让位置编码在大图上仍然有效。OCR 和小目标变好，常常是因为 token 更密，训练数据里有了文字和框。

这套骨架有三处边界，后面的工作都在碰。

* 对比学习训出来的 ViT 偏语义。小字、边缘、精细位置，在「图和句子是否配对」里可有可无。
* 把视觉空间投进词向量空间，是一个可用的接口，不是证明两种空间本来就是一回事。投影很浅时，细粒度任务会先露出缝。
* 图像只作为输入。模型写出文字，画不出一张新图，也改不了图里的一个物体。

## 理解和生成要的视觉 token 不一样

要把生成接进来，先看两种视觉 token 要的东西有多不一样。

| | 拿来理解 | 拿来生成 |
| --- | --- | --- |
| 常见前端 | CLIP / SigLIP 这类 ViT | VQ-VAE，或连续的 VAE |
| 训练信号 | 图文是否配对 | 能不能把像素或潜变量重构回来 |
| 表示 | 连续向量，偏语义 | 离散码，或低层潜变量，偏像素 |
| 结构 | 只要编码器 | 编码器之外还要一条解码回图像的路 |

理解要回答「这是不是一只猫」。生成要回答「这只猫的毛边、光和背景像素长什么样」。一个目标把细节收成类别才好泛化，另一个目标把细节留住才能画回来。码的形式也不一样：一边是连续向量，一边常常是码本里的整数。

围绕这个冲突，常见三种接法。

**一套码走到底。** Meta 的 Chameleon 用同一个 VQ 前端把图像变成离散 token，和文字排进同一条自回归序列。生成能做，因为这套码本就是为了把图编出来再还原。理解会弱，因为码本没有为「和图注对齐」优化过。后来也有工作试图在同一个分词器里同时加重构损失和对比损失，两套目标仍会抢同一组表示。

**两套编码器，一个语言模型。** DeepSeek 的 Janus / Janus-Pro 把编码拆开。理解走 SigLIP，得到语义向量，用一个两层 MLP 对齐到语言模型。生成走 VQ 码本，再用另一个适配层对齐。两边拼成一条序列，交给同一个自回归 Transformer。文本用语言模型原来的预测头，图像用另一个预测头。语义和像素各用自己的前端。代价是两套表示在进语言模型之前仍然分开。

**注意力共享，其余参数按任务分开。** 字节的 BAGEL 常被放在这条讨论里。论文并没有拿掉视觉前端：理解侧仍是 SigLIP2 的 ViT，经两层 MLP 进入语言模型；生成侧用 FLUX 的 VAE 把图像压到潜空间，再切成 token。改动发生在 Transformer 内部。理解专家处理文本和 ViT token，生成专家处理 VAE token，自注意力是共享的。所有 token 能在注意力里互相看见，前馈和一部分投影则各走各的参数。公开权重大约 14B 总参数、7B 激活，语言模型底座来自 Qwen2.5。统一发生在这次混合上，两种视觉 token 都还在。

有的介绍会把第三条写成「不要 ViT、不要扩散，图像小块直接进出一个解码器」。那是更激进的一种设计，和 BAGEL 的实际结构不是同一件事。读模型卡时可以分开看三件事：前端有几套，注意力共不共享，生成时预测的是离散码还是连续潜变量。

## 声音和视频，仍然是在加 token

图文之外再加音频、视频，产品上会叫全模态。GPT-4o 把文本、图像、音频放进同一次交互。Qwen-Omni 把「先形成要说的内容」和「把内容说成语音」拆成可以重叠的两段：前一段还在处理后半，后一段已经可以开始出声。

从这篇笔记的尺度看，新增模态没有更换 Attention。音频帧、视频帧都要先变成 token，再来占用同一条序列的长度。帧率、分辨率和采样率不同，token 的密度差很多。训练时谁占多少比例，会决定某一路会不会被另外一路盖住。序列一长，第三节那笔缓存又会变成主账单。

图像生成也未必放进同一个权重。有的系列把画图留在单独的模型里，另一个模型负责听、看、说。这是系统和数据怎么划分，不是 Attention 这一步做不到。


# 和机器人这边的笔记怎么接

视觉语言模型把语义接进了序列，距离和可通行性并没有自动变成可度量的数。只在图文上对齐过的模型，对遮挡和尺度仍然可能没有几何。之前写 [空间基础模型](/Spatial-Foundation-Model/) 时关心的就是这件事：语言 token 是一维的，机器人要的几何是三维的。

导航和操作是在这条链路外面或里面再接动作。[具身智能导航](/具身智能导航/) 和 [VLA 综述笔记](/VLA-survey-2025/) 里，视觉编码器经常仍是 ViT，语言模型仍是第三节那个解码器。动作要么变成额外的 token，要么交给一个更小的控制模块。骨架没有换，损失从「下一个词」变成了「下一个词，或者下一段轨迹」。

所以这条线到 VLM 还没有结束。等图像、语言和动作都能变成同一种序列，剩下的问题会回到 Attention 已经暴露过的地方：长度、缓存，以及每种 token 到底留下了哪一层信息。
